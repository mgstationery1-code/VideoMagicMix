# v0.1.11 均衡轮换

本版从原 VideoMagicMix 独立开发，保留旧版历史。正式入口是安装目录或完整目录包中的 `VideoMagicMix.exe`。必须保留全部配套文件，不能只搬 exe。安装见 [首页](../README.md)，入门见 [新手教程](USER_GUIDE.md)。

## 操作

1. 导入 Excel，选择完整 Hook、Body 根目录并自动匹配，上传 Body 配音并识别。
2. 在各 Body 确认目录、倍速和勾选候选。空文案继续跳过。
3. 填生成数量（默认30），关注最近条数（默认3），Body复用目标（默认50%）。
4. 点击预检并计算。系统按原始素材的近期复用及累计画面秒数均衡安排，不扫描全部成片笛卡尔积。
5. 点击“查看选材与复用明细”：查看相邻范围内的逐对复用、前10条选材、每个Body无法避开的画面、素材使用次数及秒数、Hook轮换次数。
6. 素材检查通过且近期目标达标时可以开始渲染。存在超标、完整组合重复或数量不足时，先查看明细；可修改素材/目标重检，或明确点击“接受当前未达标安排”。后端也要求对应确认，不能只绕过按钮。
7. 渲染使用同一个预检快照，修改配置、目录文件或时间轴会失效，必须重检。失败时统计已成功生成子集。

## 规则

- Hook独立均衡轮换，不计入Body复用率，不能靠换开头掩盖重复后段。
- 按规范化文件路径识别原始素材；不进行视觉检测或文件内容哈希。不同文件夹的相同内容副本仍可能低估复用。
- 某素材成片画面时长 = 原始秒数 × 所属Body目标秒数 / 该候选总原始秒数。
- 两条Body共用素材时长按每个文件双方画面秒数取较小值并求和，除以较短Body时长。
- 不论素材播放位置是否改变，共用素材仍计入。这里比较的是素材复用，不是逐帧相似度。
- 每条仅与前N条比较。30条、N=3共检查84对；统计全部精确计算，明细最多展示最高100对。不宣称整批任意两条都达标。
- 默认只使用已勾选、在倍速范围内的Body候选，不放宽倍速、不重新启用被排除候选。现有Body枚举限制保留：最多18个参与素材、每组合最多8段、最多70000候选；理论组合数仅针对当前枚举且已勾选的候选池。
- 每条尝试8个局部安排，优先减少近期超标，其次避开完整组合重复，并改善最高复用与素材曝光。重复时最多额外64次单组替换，不进行无限搜索。
- 完整组合相同会提示，不因配音/字幕方案不同就当成不同画面。不保证全局最优或穷尽所有不重复安排。
- 默认30条。0/留空按理论组合数安排，每批最多5000条并明确提示上限；正数超过5000会要求分批。请求超过理论组合数时只安排理论数量并要求确认，不把数量减少归因于复用目标。
- 项目状态仍在内存中，重启需重新导入。新测试版使用独立 `%APPDATA%/VideoMagicMix-balanced`，不会混用旧版上传文件和页面缓存。用户主动选择的外部输出目录不受此隔离影响。

## 开发与验证

核心为 `backend/rotation.py`；`backend/planning.py` 保留旧规划函数用于历史回归，但正式预检调用新轮换器。
测试：`python -m unittest discover -s tests -q`，`node --test scripts/test-window-controls.cjs`。
打包后：`python scripts/smoke_desktop.py dist-balanced-0.1.11/win-unpacked/VideoMagicMix.exe`。
完整独立后端与ASR/渲染：`python scripts/smoke_packaged.py dist-balanced-0.1.11/win-unpacked/resources/app-runtime --voice <本地语音> --render`。
